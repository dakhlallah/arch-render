# Project Continuity and Visual Storytelling

Use this mode when the user requests whole-project consistency, continuity across rooms or outputs,
design-decision tracking, a visual storytelling set, or a coherent client presentation narrative. Treat
the project as one system, not a collection of isolated images.

## Canonical Project Context

Apply the Canonical Project Context in `core-policies.md`. Maintain one approved Project Identity and
reuse it across every room, prompt, render, schedule, board, and presentation:

```text
Project and revision:
Authoritative sources:
Approved architecture and locked constraints:
Design concept and Design DNA:
Material and finish language:
Color palette:
Lighting language and scenes:
Furniture and FF&E language:
Landscape and entourage language:
Camera and composition language:
Atmosphere and color grade:
Presentation voice, grid, typography, and hierarchy:
Approved proposals:
Unknowns and source-required items:
```

Do not claim persistent memory across sessions or environments unless the Project Context was actually
saved and successfully reloaded. At the end of substantial work, provide or update a portable context
handoff. When prior assets or decisions are unavailable, request the relevant approved render, schedule,
decision log, or handoff rather than reconstructing it from memory.

## Decision register

Track consequential decisions with stable IDs:

```text
Decision ID | topic | source/request | options considered | approved choice | rationale summary |
affected rooms/outputs | approver | date/revision | dependencies | status
```

Statuses are `proposed`, `approved`, `rejected`, `superseded`, `blocked`, or `requires verification`.
Never promote a proposal into the approved Project Identity without explicit user approval.

## Consistency and conflict control

Before every new output, compare it with the approved Project Context. Check architecture, material
identity, palette, lighting, furniture language, landscape, camera language, atmosphere, grade,
presentation system, and revision.

When a conflict appears:

1. identify the conflicting sources or decisions precisely;
2. state which rooms, schedules, prompts, renders, and documents are affected;
3. preserve the last explicitly approved and authoritative state;
4. offer two or three reversible resolution options with benefits, drawbacks, dependencies, and ripple
   effects;
5. obtain approval before changing the Project Context;
6. record the resolution in the decision register.

Do not silently average incompatible styles, substitute materials, or let one new image redefine the
project.

## Furniture-layout optimization

Optimize furniture layouts only when requested or when this mode is active and a room layout is being
prepared. Read `furniture-styling-object-curation.md`. Keep every option reversible and preserve walls,
doors, windows, structure, fixed services, openings, room dimensions, circulation, access, maintenance,
and approved architecture.

Propose the smallest useful number of layout options. State the functional objective, object moves,
clearance assumptions, benefits, drawbacks, and verification required. Do not present furniture
optimization as architectural redesign or code compliance.

## Visual storytelling set

Automatically prepare a production plan and prompt set; do not automatically execute paid renders.
Use `architectural-camera-director.md` and include only views supported by the supplied sources. A typical
story may contain:

1. establishing or hero image — project identity and primary idea;
2. human-eye approach or threshold — arrival and scale;
3. primary spatial experience — program and atmosphere;
4. lifestyle view — evidence-supported occupation and use;
5. detail image — material junction, craftsmanship, or focal element;
6. room or interior sequence — only documented spaces;
7. closing image — summary, transition, or evening identity when supported.

For every shot state its purpose, source coverage, camera, lighting, linked decision IDs, continuity
locks, deliverable format, and paid-call count. Remove redundant shots. Never invent a rear facade,
interior, roof, detail, or lifestyle condition not supported by the project sources.

## Client presentation mode

Read the Client Presentation Package in `production-modes.md`. Build a coherent narrative using only
real supplied drawings and approved assets:

```text
1. Cover and project promise
2. Brief, context, and design challenge
3. Design concept and key principles
4. Approved architecture and spatial sequence
5. Materials and color story
6. Lighting, furniture, landscape, and lifestyle story as relevant
7. Hero, human-eye, detail, and room imagery
8. Key highlights and evidence
9. Decisions, options, unresolved items, and next steps
```

Adapt the page count and story to project scale. Do not fabricate plans, elevations, sections, data,
technical claims, or missing imagery. Separate existing assets, proposed assets, free layout work, and
paid render calls. Wait for approval before paid production.

## Continuity QA

Before delivery verify:

- every output uses the current approved project and revision;
- architecture and locked cameras remain preserved;
- materials, colors, lighting, furniture, landscape, lenses, and grade remain coherent;
- intentional variations are named and limited to approved axes;
- decision IDs and source IDs are traceable;
- conflicts and `Not verifiable` items are disclosed;
- the narrative order is clear and every asset has a purpose;
- no output is described as synchronized, complete, or approved without evidence.

## User-approved prompt

Use this wording verbatim when the user requests the compact continuity prompt:

```text
Treat the entire project as a unified design, never as isolated images. Always remember and apply all prior design decisions, style, materials, colors, lighting, furniture language, camera style across every room and output. Never change the approved architecture. Optimize furniture layouts only. Automatically prepare a full visual storytelling set, hero shots, detail shots, lifestyle angles. Generate a client presentation mode with a coherent narrative, design concept, materials story, and key highlights. Track design decisions. If any conflict appears, flag it and propose options while keeping overall consistency. Think and behave like a world-class multidisciplinary practice. Always protect project continuity and design integrity.
```
